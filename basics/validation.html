Validation & pagination ​

Three extractors handle what an API route reads from a request: Validated<T> parses and checks a JSON body, Pagination reads ?page and ?per_page, and Throttle<N> limits how often a user calls the route. Each one answers in the standard error format when the request is wrong.

Quick start ​

rust
use rustcms::prelude::*;

#[derive(serde::Deserialize)]
#[serde(deny_unknown_fields)]
pub struct NewTag {
    pub name: String,
}

impl Validate for NewTag {
    fn validate(&mut self) -> Result<(), ValidationErrors> {
        self.name = self.name.trim().to_owned();
        let mut errors = ValidationErrors::new();
        if self.name.is_empty() {
            errors.add("name", "is required");
        }
        if errors.is_empty() { Ok(()) } else { Err(errors) }
    }
}

pub async fn store(Validated(input): Validated<NewTag>) -> AppResult<StatusCode> {
    // `input` is parsed and valid here.
    Ok(StatusCode::CREATED)
}

Validating input ​

Validated<T> reads the JSON body like Json<T>, then calls T::validate. validate takes &mut self, so it can normalize the input (trim, drop empty values) before checking it. The demo's input for a new post:

rs
/// A new draft: a title, and an optional body.
#[derive(Deserialize)]
#[serde(deny_unknown_fields)]
pub struct NewPost {
    pub title: String,
    #[serde(default)]
    pub body: Option<String>,
}
rs
impl Validate for NewPost {
    /// Trims both; an empty body is no body.
    fn validate(&mut self) -> Result<(), ValidationErrors> {
        self.title = self.title.trim().to_owned();
        self.body = self.body.take().map(|b| b.trim().to_owned()).filter(|b| !b.is_empty());
        let mut errors = ValidationErrors::new();
        if self.title.is_empty() || self.title.chars().count() > 200 || self.title.chars().any(char::is_control) {
            errors.add("title", "must be 1 to 200 characters, without control characters");
        }
        if self.body.as_ref().is_some_and(|b| b.chars().count() > 100_000) {
            errors.add("body", "may not be longer than 100000 characters");
        }
        if errors.is_empty() { Ok(()) } else { Err(errors) }
    }
}

The handler that uses it, with a rate limit counted before the body is read:

rs
/// Creates an unpublished draft owned by the token's user.
pub async fn store(
    State(app): State<AppState>,
    auth: Auth,
    _: Throttle<CREATES_PER_MINUTE>,
    Validated(input): Validated<NewPost>,
) -> AppResult<(StatusCode, Json<PostJson>)> {
    let now = chrono::Utc::now();
    let post = post::ActiveModel {
        title: Set(input.title),
        body: Set(input.body),
        author_id: Set(Some(auth.0.user.id)),
        published: Set(false),
        created_at: Set(now),
        updated_at: Set(now),
        ..Default::default()
    }
    .insert(app.db())
    .await?;
    Ok((StatusCode::CREATED, Json(post.into())))
}

Put Validated<T> (or Json<T>) last: it consumes the body, and the extractors before it (Auth, Throttle, Path) run first.

What the client gets:

BodyAnswer
larger than the body limit413 payload_too_large
missing or unsupported JSON Content-Type (application/json, application/*+json), or malformed JSON400 bad_request
JSON, but not a T (wrong type, missing field, unknown field with deny_unknown_fields)422 with a form error (code invalid_body)
validate returns errors422 with field errors

Use #[serde(deny_unknown_fields)] on every input: a client that sends a field you do not read (author_id) gets a 422 instead of a silent success.

The body limit is http.body_limit (default 1 MiB, 1048576 bytes) for every request; give one route a larger limit with app.body_limit.

Messages ​

Write messages in plain English, without the field name ("is required"; the client shows the field). A message that follows one of the framework's templates gets a stable code clients can translate (error codes): "is required" is required, "may not be longer than 200 characters" is max_length with {"max": "200"}. Any other text gets the code custom and is shown as written.

ValidationErrors methods:

MethodDoes
ValidationErrors::new()an empty bag
ValidationErrors::field(field, message)a bag with one field message
errors.add(field, message)adds a message for a field
errors.add_form(message)adds a message for the whole form
errors.is_empty()no message recorded
errors.into_result()Ok(()) when empty, else Err(AppError::Validation(..))

See Errors for the response format.

Pagination ​

Pagination reads ?page and ?per_page; ApiPage::fetch runs the query for that page and counts every row. The demo's list of published posts:

rs
/// Published posts (publication date reached, not trashed), newest first.
pub async fn index(State(app): State<AppState>, page: Pagination) -> AppResult<Json<ApiPage<PostJson>>> {
    let select = post::Entity::find()
        // Trashed posts (soft deletes) are not published.
        .filter(post::Column::DeletedAt.is_null())
        .filter(post::Column::Published.eq(true))
        .filter(post::Column::PublishedAt.is_not_null())
        .filter(post::Column::PublishedAt.lte(chrono::Utc::now()))
        .order_by_desc(post::Column::PublishedAt)
        .order_by_desc(post::Column::Id);
    Ok(Json(ApiPage::fetch(select, app.db(), &page, PostJson::from).await?))
}

The response:

json
{
  "data": [{ "id": "42", "title": "Hello", "body": null, "published": true, "published_at": "2026-10-01T08:00:00Z" }],
  "meta": { "page": 1, "perPage": 20, "total": 15, "lastPage": 1 }
}
ParameterRangeDefaultConstant
page1 to 10,0001rustcms::http::api::MAX_PAGE
per_page1 to 10020MAX_PER_PAGE, DEFAULT_PER_PAGE
  • Out of range, not a number, empty or given twice → 422 on that parameter ("must be a number from 1 to 10000", "may only be given once"). Other query parameters are left to your handler.
  • A page past the last one answers an empty data with the same meta.
  • lastPage is at least 1, even for an empty list.
  • Always order the query, and end with a unique column (the key): without a total order, rows can move between pages.

Pagination can also be built by hand: Pagination::new(page, per_page) checks the bounds, Pagination::from_query(Some("page=2")) reads a raw query string; both return Result<Pagination, ValidationErrors>. page.page() and page.per_page() read the values. ApiPage<T> has two public fields, data and meta (rustcms::http::ApiPageMeta: page, per_page, total, last_page).

Rate limiting ​

Throttle<N> allows N requests a minute per user and route, then answers 429 with Retry-After (seconds). Put it before the body extractor: attempts are counted before the body is read and validated, so invalid requests count too.

  • The counter key is the user and the route pattern (/api/v1/posts), not the method: if the GET and the POST handlers of one path both take Throttle, they share one counter. Handlers without Throttle do not count.
  • It needs a token: without one, the request is 401, even on a public route. Use it on routes with Access::authenticated() or Access::can(…).
  • Limits are kept in memory, per instance. With Redis configured, every instance counts in Redis (Several instances); if Redis does not answer, the request fails (500) rather than going through unlimited.

Pitfalls ​

  • validate runs only after the body parsed as a T: a 422 for a wrong shape carries a form error, not field errors.
  • Messages are sorted by field name in the response (errors is a map), and kept in the order you added them within a field.
  • Field rules here apply to your API routes only. Admin forms validate with their own field rules, including the static options of selects and checkbox lists (options).

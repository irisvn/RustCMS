Limitations ​

What RustCMS does not do yet, the fixed limits it enforces, and behaviours to know before relying on it. Read it when you plan an application, so a limit does not surprise you in production.

Not supported yet ​

  • Pivot columns in the record's own form (a BelongsToManySelect links with the pivot's database defaults; edit pivot columns in the relation manager), and a BelongsToManySelect for relations with required pivot fields or records with more than 100 links; belongs-to-many to the same resource, two relations over one pivot table, or to a resource declaring lock_parent.
  • Excel files; dashboard widgets with sums or averages (widgets count or list records); charts in time zones other than UTC.
  • Email verification flows (invitations mark the address verified).
  • Mail rate limits shared between instances (max_per_minute counts per process); DKIM signing; attachments.
  • Settings of kinds other than text, textarea, integer (i32), boolean, select, key/value, date, secret and media (one file, or a list) (store larger numbers or decimals as text).
  • Translations of content (only the interface is translated: English, Vietnamese).
  • Composite primary keys; sorting by related columns.
  • Column types without a wire kind: smallint, tinyint, unsigned integers, time, binary, enums and arrays cannot be admin fields (Wire format).
  • Server-side image resizing (the Media grid scales the originals in the browser), range requests, presigned or public media URLs (files are served only through the panel, after an authorization check; add your own route for public files).
  • MariaDB; Redis Cluster.
  • Idempotency keys outside resource creates (relation creates included), actions, media uploads, CSV import uploads and background export requests.
  • Managing API-guard roles from the panel (use rustcms role:assign).
  • Cron expressions in a time zone other than UTC.
  • Reactions on inputs inside repeater rows, on settings pages and in action forms; computed options (options_fn) anywhere but a resource form's own inputs (Forms).

Writes in flight ​

Signing out one session, or revoking one API token, does not abort a change that the same credential already started. Sign-out everywhere, password changes and disabling a user apply from the next request (with the opt-in auth.jwt.session_cache_ms and auth.permission_generation_cache_ms, within those times on other instances, see Credential revocation), and changes made through RbacService re-check the credential under lock. A resource write keeps the permissions it started with.

Background work ​

  • Schedules run only in rustcms serve, never in console commands, queue:work or tests (Scheduling).
  • The auth, idempotency, media and exports clean-ups are framework schedules, run only by serve with the scheduler: a deployment without it runs them from cron (Data retention). Each instance sweeps the files it staged itself (serve, queue:work).

Databases ​

  • SQLite decimals are stored as REAL: values are shown at the column scale, but precision is that of a 64-bit float. Use PostgreSQL or MySQL for money.
  • Search compares LOWER(column) LIKE LOWER(pattern): case-insensitive for all of Unicode on PostgreSQL, for ASCII only on SQLite. It uses no index; full-text search is out of scope.
  • Named locks on MySQL: rustcms::db::xact_lock works only with the names the framework creates (rbac, lineage:<slot>, idem:<slot>); other names fail on MySQL (Database schema).
  • MySQL specifics (collation, non-transactional DDL) are in Database.

Deployments ​

One instance, or several sharing one standalone Redis and shared media storage (Several instances). Password-hashing and upload concurrency limits are per instance; runtime branding is cached per instance, and each instance runs its own realtime hubs.

Size ​

The panel ships as one JavaScript file of about 1.36 MB (about 417 KB gzipped) and one stylesheet of about 42 KB (about 8 KB gzipped), embedded in the binary. The server sends them uncompressed, with a one-year immutable cache: put a compressing reverse proxy in front if the first load matters. Binary sizes depend on the features and drivers you build with; measure your own release build.

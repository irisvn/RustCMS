What is kept, and for how long ​

RustCMS deletes expired data on its own, once per period, in background passes. This page lists what each table keeps, which pass deletes it, and which commands do the same from cron when no long-running process is up.

Background passes ​

The auth, idempotency, media and exports cleanups are framework schedules (rustcms.auth-prune, rustcms.idempotency-prune, rustcms.media-prune.<disk>, rustcms.exports-prune.<disk>): they run only in serve with [schedule] enabled (the default, except in API mode), once per slot across instances (UTC), never in queue:work, console commands or tests. They show on System → Schedules and in schedule:list with their runs and summaries.

Files an instance stages on its own disk are its own to sweep: every serve (whatever its mode) and queue:work removes the abandoned ones (uploads, exports and imports interrupted by a crash, older than an hour) at start and every 10 minutes; queue:work --once and media:prune do it once.

From cron ​

When serve is not running all the time (workers only, maintenance windows), run the commands from cron:

sh
rustcms session:prune       # sessions and ended JWT sign-ins
rustcms schedule:run rustcms.auth-prune   # or: the whole auth cleanup, reset links included
rustcms audit:prune
rustcms idempotency:prune
rustcms media:prune         # and this instance's abandoned staged files
rustcms schedule:run rustcms.exports-prune.local   # or .s3: the disk in use
rustcms queue:work --once   # failed jobs, receipts, job and schedule history (and the ready jobs)

rustcms schedule:run rustcms.auth-prune runs the whole auth cleanup once, reset and invitation links included (no other command deletes those), and records the run in the schedule history; it does not prune that history, nor schedule claims (only serve's scheduler and the workers do). schedule:run rustcms.exports-prune.<disk> deletes expired exports and imports the same way.

Personal data ​

Queued jobs hold their payload until they are done or, failed, until pruned: a password reset job holds the address it was asked for (never a link). Audit entries hold user ids, addresses and user agents. Keep backups of the database as protected as the database itself.
